## Scheduled Maintenance

TeSS relies on cron jobs generated by Whenever (`config/schedule.rb`).

| Task | Schedule | Rake Command(s) | Purpose | Key Code |
|------|----------|-----------------|---------|----------|
| Automated ingestion | Daily 03:00 | `tess:automated_ingestion` | Run scraper across configured Sources | `lib/tasks/tess.rake:133`, `lib/scraper.rb` |
| LLM post-processing | Daily 03:00 | `tess:llm_post_processing` | Enrich newly scraped events | `lib/llm.rb` |
| Process subscriptions | Daily 02:00 | `tess:process_subscriptions` | Email subscription digests | `lib/tasks/tess.rake:113` |
| Event curation mails | Monday 09:00 | `tess:event_curation_mails` | Prompt providers to approve content | `lib/tasks/tess.rake:152` |
| Rebuild autocomplete suggestions | Tuesday 05:00 | `tess:rebuild_autocomplete_suggestions` | Refresh autocomplete dataset | `lib/tasks/tess.rake:237` |
| Check resource URLs | Daily 06:00 | `tess:check_resource_urls` | Dead link monitoring | `lib/tasks/check_urls.rake:19` |
| Delete old declined events | Daily 04:00 | `delete_events:delete_old` | Housekeeping for declined events | `lib/tasks/delete_events.rake` |
| Sitemap refresh | Daily 01:00 | `sitemap:refresh` | Update public sitemap | `config/schedule.rb` |

## Ingestion Pipeline Internals

1. **Configuration Sources**
   - Built-in defaults in `lib/scraper.rb` provide the scraper username (`scraper`), role (`scraper_user`), logging target, and empty source list.
   - Optional overrides in `config/ingestion.yml` (loaded via `TeSS::Config.ingestion`).
   - Approved `Source` records stored in PostgreSQL (managed via UI/Admin).

2. **Scraper Execution** (`lib/scraper.rb`)
   - Instantiates `Scraper::ConfigSource` objects for static config and iterates over approved `Source` ActiveRecord records (`lib/scraper.rb:68-77`).
   - Uses `Ingestors::IngestorFactory` to pick the correct ingestor class (`lib/ingestors/ingestor_factory.rb`).
   - Captures run statistics on the `Source` record (records read/written, log output).

3. **Follow-up Processing**
   - Geocoding is queued via `GeocodingWorker` if event addresses changed.
   - BioPortal topic suggestions run asynchronously through `EditSuggestionWorker` when enabled.
   - Subscription and curation notifications are deferred to scheduled jobs.

## LLM Integration

- **Services**
  - ChatGPT (`lib/llm/chatgpt_service.rb`).
  - Willma (`lib/llm/willma_service.rb`).
  - Registered through `Llm.service_hash` and selected via `TeSS::Config.llm_scraper['model']` / `model_version`.

- **Usage Modes**
  - **Scraping**: `Ingestors::FourtuLlmIngestor` leverages LLM prompts to structure event data from free-form sources.
  - **Post-processing**: `tess:llm_post_processing` iterates over events flagged by `Event.not_finished.needs_processing(prompt)` updating `LlmInteraction` records (`lib/llm.rb`, `app/models/llm_interaction.rb`).

- **Configuration**
  - Controlled via `TeSS::Config.llm_scraper` entries in `config/tess.yml`.
  - Prompts stored under `lib/llm/llm_prompts/` for easier iteration.
  - Leave both `model` and `model_version` blank (default) to keep LLM features disabled.

## Background Jobs & Queues

- Sidekiq queues defined in `config/sidekiq.yml`: `default`, `mailers`, `slack_notifications`, `source_testing`.
- Redis connection configured via `TeSS::Config.redis_url` (with separate DB per environment).
- Notable workers:
  - `GeocodingWorker` (`app/workers/geocoding_worker.rb`) – caches lookups in Redis.
  - `EditSuggestionWorker` (`app/workers/edit_suggestion_worker.rb`) – BioPortal annotations.
  - `SourceTestWorker` (`app/workers/source_test_worker.rb`) – on-demand Source validation (uses `Sidekiq::Status`).
  - `SlackNotificationJob` (`app/jobs/slack_notification_job.rb`) – production-only notifications.
- Check `config/initializers/sidekiq.rb` for middleware and status tracking configuration.

## Authentication Providers

- **Local Devise** authentication with optional registrations/invitations controlled via `TeSS::Config.feature` toggles (`app/models/user.rb`).
- **OmniAuth integrations** (OpenID Connect):
  - Life Science AAI / LS-Login (`config/initializers/omniauth/ls_login.rb`).
  - Australian Access Federation (AAF) (`config/initializers/omniauth/aaf.rb`).
  - Tuakiri (New Zealand) (`config/initializers/omniauth/tuakiri.rb`).
- **API Tokens**: `acts_as_token_authenticatable` in `User` and `ApplicationController`’s `acts_as_token_authentication_handler_for` for REST clients.
- **Authorization**: Pundit policies using `Pundit::CurrentContext` to incorporate request parameters.

## Model Concerns Reference

Shared modules located in `app/models/concerns/` (plus supporting modules under `lib/`). Key groups include:

- **Ingestion & Curation**: `Scrapable`, `LockableFields`, `HasExternalResources`, `HasContentProvider`, `CurationQueue`.
- **Discovery & Metadata**: `Searchable`, `HasEdamTerms`, `HasSuggestions`, `HasAssociatedNodes`, `AutocompleteManager` (defined in `lib/autocomplete_manager.rb`).
- **Governance & Auditing**: `LogParameterChanges`, `HasTestJob`, `Collaboratable`, `WithTimezone`, `IdentifiersDotOrg`.
- **User Experience**: `HasFriendlyId`, `HasLanguage`, `HasLicence`, `HasDifficultyLevel`.

## Configuration Quick Reference

- `config/tess.yml`: Instance-specific settings (features, ingestion defaults, placeholders, etc.).
- `config/ingestion.yml`: Optional ingestion-only overrides read by `TeSS::Config.ingestion`.
- `config/sidekiq.yml`: Queue definitions and concurrency.
- `config/schedule.yml`: Optional overrides for Whenever schedules (`config/schedule.rb` loads this file if present).
- `config/secrets.yml` / credentials: API keys (Recaptcha, Google Maps, FAIRsharing, OmniAuth clients).

## Troubleshooting Notes

### Ingestion Failures

- **Symptom:** Source marked as failed.
- **Diagnostics:** Review `Source#log`, check `log/scraper.log` if configured, verify network access to remote endpoint, ensure tokens are valid.
- **Next Steps:** Retry from UI (Source > Test) or run `bundle exec rake tess:automated_ingestion` locally.

### Geocoding Delays

- Ensure Redis is reachable (check `redis-cli ping`).
- Confirm `TeSS::Config.feature['geocoding']` is enabled and Sidekiq queue is being processed.

### Search Index Out of Sync

- Verify Solr container/process running.
- Reindex via `bundle exec rake sunspot:reindex` (can be heavy; schedule during low-traffic periods).

### Sidekiq Queue Backlog

- Inspect the Web UI (`/sidekiq`) for failing jobs.
- Check `log/sidekiq.log` for errors.
- Ensure Redis memory and connection pool is healthy.
